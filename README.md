# 铁道烽烟：军阀时代

**Railway Warlords · 中国近代与亚洲战区六边格回合策略游戏**

[中文](README.md) · [English](README.en.md) · [全部剧本](docs/SCENARIO_INDEX.md) · [程序文档](docs/00_程序文档索引.md) · [当前完成度](docs/23_当前完成度评估.md)

用铁路调动军队，用城市维持战争。炮兵打开城防缺口，步骑兵夺取节点，工兵抢通交通线；粮秣、弹药、士气和外交共同决定一场战局能走多远。

本项目以中国军阀战争为核心，扩展到 **1840—1940 年亚洲时间锚点**。使用 **Godot 4.7.2 / GDScript**，面向 **Windows x86_64 与 Android ARM64 / ARMv7**，当前为 **0.2.14 可玩测试版**。离线单机；现有游戏界面为简体中文，README 提供中英双语，游戏内英文界面尚未实现。

美术和交互以《欧陆战争6》为主要对照，玩法也参考《世界征服者》系列的战役、征服和军团结构。项目使用自己的代码、生成素材和有来源的地理数据，当前成果及差距均按实际记录，尚未达到参考作品的商业完成度。

## 开始游玩与操作

| 平台 | 运行方法 | 当前范围 |
| --- | --- | --- |
| Windows | 已导出版本运行 `build/windows/RailwayWarlords.exe` | x86_64，资源嵌入；玩家无需安装 Godot 或 Python |
| Android | 安装自行导出的 `build/android/RailwayWarlords.apk` | 横屏，ARM64 / ARMv7，最低 Android 7.0 / API 24；当前验证包 target SDK 36 |
| Godot 编辑器 | 导入根目录 `project.godot`，等待资源导入，按 **F5** | Godot 4.7.2、Compatibility 渲染器 |

仓库保留完整源码和运行资源；EXE、APK、引擎缓存与私有签名不随 Git 提交。原始 PNG 约 2.13 GiB，首次克隆和导入需要预留时间及数 GB 磁盘空间；本地交付包独立保留。

### 第一局建议

1. 进入“战役”，从已解锁首关开始，阅读目标和失败条件。
2. 选择炮兵与敌方目标，查看伤害／反击预览，再点击底部确认攻击。
3. 击破城防并清除驻军，让具备占领能力的部队进入城市；炮兵无法直接占城。
4. 留意粮弹、补给和士气，用城市生产、铁路投送和工兵抢修维持战线。
5. 结束本方阶段，观察 AI 按相同规则行动。结算后领取星级和成长奖励。
6. 在指挥部配置下一场的将领、科技和战法；旧战局的成长快照保持开局状态。

## 回合、战斗与胜利

```mermaid
flowchart LR
    A[收入、补给与阶段事件] --> B[侦察与目标检查]
    B --> C[移动、进攻、战法与生产]
    C --> D[命令校验与原子结算]
    D --> E[行军、交战与状态反馈]
    E --> C
    C --> F[结束本方阶段]
    F --> G[AI 按相同规则行动]
    G --> H[目标与胜负判定]
    H --> A
```

- **移动**：加权六边格寻路，检查地形成本、控制区、可见信息、桥梁、渡口和线路。移动可分段，隐藏敌军按遭遇规则处理。
- **攻击**：每编队每阶段一次主攻击，消耗弹药，攻击后行动点归零。射程、克制、地形、当前兵力、士气、压制、将领与科技共同作用。
- **反击**：使用受击后的实际兵力和压制；普通部队每整回合一次，机枪有额外反击能力；仍需满足射程与城防限制。
- **城市**：城防和驻军独立记录生命。破防不等于易手，清除驻军后还需可占领部队进入。
- **随机骰**：预览只读且不消耗随机流；正式结算记录攻防骰、修正、伤害与反击。随机状态随存档保存，可重放核对。
- **视野**：地形视线、探索、侦察、最后目击与同盟共享控制情报，AI 使用可见信息并提交同一命令接口。
- **表现**：行军、持续朝向、炮弹、枪口、受击、飘字、击溃、占领、侦察／轰炸和骰面由实际状态事件驱动。

任务支持占领、连续守城、歼灭目标编队、俘获／击溃指定将领、护送、生存和抢修等目标。保护对象损失、主将受伤等失败条件优先处理；星级结合任务阈值和损失条件计算。

征服／自由世界围绕战略节点、阵营生存和同盟结算；到期按剧本积分。军阀征服通常为 80 回合，亚洲自由世界为 180 回合。推演日期是游戏日历，不是逐日战史。

难度包含普通成长、困难与标准化挑战；当前困难选项标注敌军攻击 +10%。军团以标准化成长开局，部署预算和城市生产军费分别记账。

## 兵种、将领与成长

| 基础兵种 | 主要任务与限制 |
| --- | --- |
| 地方守备队 | 低成本守点、补充战线与占领 |
| 步兵团 | 主力占城、守线与合击 |
| 突击营 | 突破与近距离进攻，受年代限制 |
| 机枪营 | 压制、据点防御与反击 |
| 骑兵团 | 高机动、侧翼、追击与占领 |
| 工兵营 | 线路抢修、工程与占领 |
| 野战炮营 | 远程压制和破防，不能占城 |
| 重炮营 | 重型远程火力，依赖生产与补给 |
| 装甲汽车队 | 机动和占领，受年代、地形与供给约束 |
| 装甲列车 | 铁路火力，依赖完整可用线路 |
| 江防炮艇 | 内河支援、护航 |
| 运输船 | 港口装载、航行与卸载，需陆军完成占领 |
| 沿海炮舰 | 沿海火力与岸轰 |

完整生命、攻防、行动、射程、造价与年代见[兵种数值表](docs/UNIT_REFERENCE.md)，以 [units.json](content/definitions/units.json) 为准。`stack` 是游戏编队层数，不能直接等同于历史某个营、团或旅。兵种还受剧本白名单限制。

29 位人物定义涵盖吴佩孚、张作霖、冯玉祥、阎锡山、林则徐、洪秀全、曾国藩、孙中山、蒋介石、李宗仁等。是否在场、所属阵营和可部署范围取决于年代剧本；专长和星级是玩法数值，肖像与归属仍需独立复核。

指挥部管理将领、军衔、主动／被动战法、勋章、科技和精锐解锁。局内经验支持晋升；长期成长在开局冻结为快照，局外升级不追溯改变进行中战局。奖励有去重账本，重复查看结果不重复领取。

三类精锐对应突击、骑兵、炮兵，具有章节与科技门槛。18 个战法涵盖炮火压制、步兵强袭、骑兵迂回、应急给养、铁路优先、侦察、筑垒、现场维修与协同射击。

## 城市、经济、补给与外交

| 资源／指标 | 游戏用途 |
| --- | --- |
| 军费 | 征募、军饷、设施、维修与部分外交 |
| 粮秣 | 给养与持续作战 |
| 军备 | 征募、补员、弹药与维修 |
| 燃油 | 交通和机动压力；早期年代同样属于玩法抽象 |
| 白银 | 贸易、外交与储备 |
| 兵源 | 城市征募和补员容量 |
| 士气／压制 | 给养、受击与持续战斗能力 |
| 战争疲劳／合法性 | 经济收益和长期战争压力 |
| 殖民影响 | 港口、贸易与外交抽象 |

**城市**记录等级、城防、兵源、驻军与队列。12 类设施为兵营、机枪工坊、兵工厂、车站、港口、机场、补给站、医院、工事、电报站、贸易站、粮仓。一般设施限 4 槽，工事不占槽，可拆除腾位；部署位置被堵时完成的队列保留。

**铁路**同时校验势力运力池和全路径区间运力；敌方控制、损坏与通行权会影响投送。工兵按阶段维修，离开位置时暂停。铁路既运兵也影响补给，装甲列车依赖完整线路。

**补给**沿城市、道路、铁路与江海网络传播；断路和外交权限会改变补给状态，进一步影响行动、火力、弹药和士气。长期断粮可造成兵力损失。舰船装卸另有港口、行动与卸载地格约束。

**航空**来自允许建设机场的城市，检查出动数、范围、资源、弹药与天气，提供侦察和轰炸命令。

**外交**包含宣战、停战、同盟、通行、补给权、援助和贸易。结盟不直接转移城市所有权，共享胜利按关系图结算；玩家可从真实地理和年代起点改变后续进程。

以上构成经济—生产—运输—作战循环。资源、财政与政治数值服务于游戏平衡，不是历史统计，也尚未达到《欧陆风云》系列完整国家治理深度。公式与实现见[经济、物资与多元军队](docs/21_经济物资士气与多元军队.md)。

总格数包括陆地、水体与受限格，不能等同于可部署面积。京津、京奉和东部征服地图宽、高分别扩展五倍，基础操作蜂窝半径保持 **48 像素**。亚洲层范围 **20°E—180°E、10°S—80°N**，是大陆战略尺度，不是全亚洲村级地图，各地区细节密度也不相同。

- **海岸与主河**：Natural Earth 源几何；城市为真实坐标，铁路依年代资料。
- **细河网**：战术层增加 24,268 条细河段和 31 条主河替代显示段，共 24,299 条记录；亚洲层另保留 694 条来源细河段。按等级与缩放显示，不宣称全量小溪覆盖。
- **地形**：Tilezen／SRTM 等来源高程。亚洲层由 54 张原始 GeoTIFF、33,696 个登记采样点构建粗地形，格网名义半径 150 千米、采样支持范围 100 千米。
- **地表**：草土、旱草、岩土、林下土、湿土、水面、细沙、砾土、冲积土按来源生态区、高程和地理条件选材。
- **地景**：多种树冠、丘陵、山脊、高峰、岸线、露岩、芦苇和地区建筑，按脚点、坡向和空间排重放置。
- **聚落**：首都、省城、县城、集镇和村落分级；增加 67 处有来源的标记，随缩放显示，支持隶属和地方说明查询。
- **控制层**：半透明势力色保留地表，基础控制色场约 0.20—0.23，局部城市影响区覆盖为 0.26；随当前据点归属变化，不冒充精确历史军事边界。

地图资源从早期 74 张扩为 **970 张，约 13.11 倍**。0.2.12 的 796 张独立扩充图包含 **176 张地表、480 张地景、140 张建筑**；0.2.13 增加 **80 张地域细节原图**，0.2.14 再增加 **20 张连续绘制底材**。显示缩放、镜像、染色不计为新增原图。

20 类地表包括温带草甸、旱生草原、荒漠草原、风成沙地、戈壁砾地、盐生草甸、高山草甸、高寒草原、苔原、寒带腐殖层、温带落叶层、针叶层、亚热带湿润土、热带腐土、旱林灌丛底材、热带草原底材、洪泛草甸、河谷冲积地表、风化岩坡和峰岭碎岩。每类一张连续底材与四张细节原图，按生态区、高程与既有河谷选取，同类六邻格不复用同一张细节源图。势力归属以独立半透明层覆盖。

连续底材按世界坐标取样，跨格保持同一笔触位置；原四张细节纹理以战术 0.22 / 战略 0.14 强度叠加，减轻砂纸感和逐格斑块。主河与细河段采用统一河级宽度和连续明暗岸缘，宽度为制图符号。

![程序内可交互地形图鉴：草地与荒漠](docs/media/terrain-atlas-grass.png)

在游戏说明或地格详情中打开“地形图鉴”，可查看三页 20 类及每类一张连续底材和四张细节原图。它们属于地域地表表现；通行、掩护和水陆判定以格子实际规则地形为准。详见[20 类地表及来源门控](docs/30_二十类地域地表与纹理整改.md)和[连续地表与水系层次](docs/31_连续地表与水系层次.md)。

真实地理、年代行政资料、人物和编制分别登记来源。现代潜在生态区只指导代表性材质，不能当作逐年历史森林、湿地或土地利用调查；现代水系不自动代表历史河道。生成建筑是地区符号，不是具名城市街区复原。

亚洲局部任务当前仍使用粗尺度战略节点，部分地点映射到邻近节点。兵力、`stack`、收入、天气、部署与目标是玩法数据；日期、人物装备、编制与起局控制仍需逐条复核。见[历史数据](docs/19_亚洲全境时间线与史实数据.md)、[地图依据](docs/07_历史地理与地图美术.md)、[地表与细水系](docs/29_地表材质与细水系.md)。

## 完整内容与时间线

**军阀战区**：18 场原有战役分为 1920、1922、1924 三组，并有相应东部中国征服。城市、铁路、补给和军事集团竞争是核心。1924 征服包含日期触发的北京政变与国民军状态变化，玩家后续结果遵循游戏规则。

| 亚洲起点 | 当前题材 | 阅读边界 |
| --- | --- | --- |
| 1840 | 清、英国与亚洲势力；鸦片战争任务组 | 组内任务延伸到 1841、1842，分组年份不是每关日期 |
| 1860 | 英法战事、北方通道与太平天国相关任务 | 战争、地区与阵营关系分别登记 |
| 1890 | 甲午前夜及延伸到 1894、1895 的任务 | 1890 不是义和团运动日期；日俄战争尚无独立完整战役组 |
| 1900 | 大沽、天津、北京与八国联军相关任务 | 不同阶段历史兵力不直接等同于游戏编队 |
| 1917 | 护法、北京政局与俄国政权变动 | 部分标题与登记日期仍待历史复核 |
| 1927 | 北伐、武汉、上海和江西相关任务 | 事件题材、作战日期与目标分别审查 |
| 1940 | 中国交通线、湖北与印度支那任务 | 装备、人物和部署按独立审核状态记录 |

每个亚洲时间锚有一个自由世界和三场任务，共 **7 个起点、21 场任务**。`province_scope` 最多三个省级／地区条目；它是任务编排范围，不表示已绘制全亚洲所有历史省界。当前记录 30 个 OOB 编制，保留兵力范围和来源状态，不补造无法确认的小队和军官。

12 项军团挑战训练合击、压制、工兵、补给、铁路、侦察、江防和跨江装卸，明确属于演习。全部名称、日期、地图和回合上限见[61 个剧本完整索引](docs/SCENARIO_INDEX.md)。

## 保存与设置

- **保存**：5 个手动槽、3 个轮换自动槽；Android 切后台自动保存。损坏时尝试备份，内容／规则指纹不兼容时明确拒绝载入。
- **版本**：本版地形订正改变内容指纹，旧进行中战局使用对应旧版继续；成长档案另存，不保证所有战局跨版本兼容。
- **暂停**：弹窗打开时 AI 停止提交命令，后台结果按战局和版本校验，防止旧命令重复生效。
- **设置**：音乐、音效、独立音量、网格、演出速度、交战小窗、减少晃动和 100%／120%／150% 字号。
- **手机**：横屏、大按钮、安全区、拖动和双指缩放；Motorola X30 为目标样机，真机验收单列。
- **存储**：Windows 为 Godot `user://`，通常是 `%APPDATA%/Godot/app_userdata/铁道烽烟：军阀时代/`；Android 为应用私有目录。成就与战绩榜均在本机。
- **联网**：当前无多人或联网排行；APK 不申请网络、相机、麦克风和外部存储权限。

<a id="development"></a>
## 源码运行与双端导出

### 克隆和运行

使用原生 Windows 工具；项目禁止本地 Docker、WSL、虚拟机和 Android 模拟器。

```powershell
git clone git@github.com:wikigsroom/railway-warlords.git
Set-Location railway-warlords

# 将 Godot 4.7.2 原生控制台程序配置到 PATH，命名为 godot，或替换为绝对路径。
godot --headless --path . --editor --import --quit
godot --path . --editor
# 直接运行游戏：
godot --path .
```

无需 Git LFS。PNG 保留原始字节，`*.import` 保留导入参数，`.godot/` 在本机重新生成。运行核心游戏无需 Python、生成网关或原电脑私有配置。

### Windows

安装与引擎完全对应的 **Godot 4.7.2 官方导出模板**。项目的 `Windows` 预设使用 x86_64、Compatibility 渲染与嵌入式 PCK。

```powershell
New-Item -ItemType Directory -Force build/windows | Out-Null
godot --headless --path . --export-release "Windows" "build/windows/RailwayWarlords.exe"
```

预设未启用商业代码签名，正式发行时使用自己的签名流程。

### Android

配置原生 **JDK 21、Android SDK** 与对应导出模板，在 Godot 编辑器设置中填写本机 Java／SDK 路径。当前验证 APK 为 **minSDK 24 / targetSDK 36**，开启 ARM64、ARMv7，关闭 x86 模拟器目标。

```powershell
New-Item -ItemType Directory -Force build/android | Out-Null
godot --headless --path . --export-debug "Android" "build/android/RailwayWarlords-debug.apk"
adb install -r build/android/RailwayWarlords-debug.apk
adb shell monkey -p org.railwaywarlords.game -c android.intent.category.LAUNCHER 1
```

发布前在 Godot 私有导出凭据或环境变量配置自己的 release keystore、alias、密码，避免写进版本控制，再导出：

```powershell
godot --headless --path . --export-release "Android" "build/android/RailwayWarlords.apk"
```

应用 ID 为 `org.railwaywarlords.game`，当前 versionCode 17。覆盖更新必须使用相同签名；自行签名不能覆盖原签名安装。仓库的 release 凭据字段为空。

### 自动化工具的范围

`tools/` 包含构建、回归、地理编译、素材核验、录像与交付审查脚本，部分保留原工作区布局：

```text
workspace/
├── .toolchain/              # 原生引擎与私有签名
├── design/铁道烽烟/          # 原始设计与登记表
├── output/                  # 原图、地理原始档案与旧交付
└── game/railway_warlords/    # 本仓库原始位置
```

外部档案不属于独立克隆。`build_release.py` 等原工作区助手含机器路径，需要调整；从原始地理资料重建也需取得相应档案。独立克隆可用上面的 Godot 命令直接运行和导出，编译后地理数据及完整运行美术已经包含。依赖分层见[开发环境说明](docs/DEVELOPMENT.md)。
