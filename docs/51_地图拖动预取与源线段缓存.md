# 0.2.33 地图拖动预取与源线段缓存

本轮针对拖动地图时的素材读取与重绘停顿，保留既有地表、河道、山体、控制色与操作蜂窝。整体《欧陆战争6》画质和完整动作体系仍未完成，本轮是其中的流畅度修订。

## 实现与边界

相机周边的独立地形原图提前读取，每次最多两个后台请求、128个候选，地图纹理缓存仍为384项。每帧只领取已完成的请求；突然跳转到尚未准备的区域时，仍同步补齐真实原图。它不保证首次进场、跨大区跳转或所有设备的加载尖峰都消失。已有导入贴图、原图和来源记录不变，未新增、裁取或拼接图片。

省界、城市控制区边缘按32个来源线段建立索引，仅提交与保守视区相交的连续部分。线段顶点和内部连接顺序不改动；临近分段重新合并成连续折线。铁路缓存沿用原先的曲线与枕木起点，运行日期、通行条件和损坏颜色仍从当前战局读取。地图或年代行政层切换时重建相应来源索引。

地块细节网格按16×16来源格缓存，维持原贴图编号、世界坐标、UV、透明度和全局贴图绘制顺序。最多保留96个细节分区；超大视口的额外网格由当前绘制持有，避免循环淘汰全部工作集。地图切换会清空旧分区。绘制计数包含保守离屏分区边缘，不能解释为同屏可见格数。原有连续底材与真实岸线裁切继续独立使用。

异步读取遵循[Godot ResourceLoader文档](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html)：完成状态与领取结果分别处理；当前必需而未完成的资源仍可能阻塞。退出程序时取消尚未开始的预取，并领取本程序最多两个在途任务的结果，避免快速退出时遗留加载任务。该等待仅发生在退出阶段。游戏运行无需连接任何素材或音乐生成服务。

## 原图与画面核对

在同一原生Godot程序中，分别使用从0.2.32提交复制的完整静态地图、细节网格绘制方法与新方法，拍摄三个完整1920×1080视口。三组每个像素、每个通道均一致，PNG字节也一致。此核对证明这三个固定镜头的绘制保持，不证明所有地图、缩放和运动帧均相同。

原始六张截图、调用入口与逐像素结果见[对照目录](../reports/map_pan_v0233/renderer_comparison_02/pixel_comparison.json)。其中驱动遗留名称`beijing`实际是京奉战区的0.62倍缩放镜头，不能当作北京城区验收；另外两个镜头为山地和武汉。早期对照工具因旧源码换行转换错误失败，记录保留，随后已修复；失败轮次不计入通过项。

## 检查、性能与交付状态

新增47项组件检查分别覆盖[源线段与铁路](../reports/map_pan_v0233/final_components_02/source_line_tests.json)、[异步原图读取](../reports/map_pan_v0233/final_components_02/prefetch_tests.json)、[细节网格缓存](../reports/map_pan_v0233/final_components_02/fine_cache_tests.json)。网格检查逐项比较旧方法的顶点、颜色、UV和顺序；线段检查另用几何相交判断覆盖长跨越、负坐标和视区边缘。它们不代替最终程序的GPU、整幅画面或手机验收。

625项组件、48项正式EXE地表GPU和58项地图布局检查通过，共731项专项；10张最终程序整幅画面已完整查看。Windows和签名Android/code38绑定同一冻结源码身份；APK的v2/v3签名、双ARM架构、141份数据/说明、2,509张贴图及3首配乐载荷均已核对。物理X30验收仍未完成，既有历史内容、全兵种动作和整体美术仍有缺口。

四轮开发复测依次为旧89.073、新29.639、新29.964、旧92.451毫秒（95分位），每轮180帧且全部保持窗口焦点；同步读取次数依次为旧16、新1、新1、旧16。后台其他应用负载未全部控制，不属于两份发布二进制的严格实验室对照，也不证明手机流畅度。
