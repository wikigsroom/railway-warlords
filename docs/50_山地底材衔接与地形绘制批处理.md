# 0.2.32 山地底材衔接与地形绘制批处理

本轮减轻绿色山体与大片灰岩底之间的割裂，并合并地形阴影和等高线的绘制。它是可玩测试版的局部修订，整体美术、河网细节与拖动流畅度仍未达到《欧陆战争6》的目标。

## 山体与底材

旧实现把丘陵、山地一律画成完整的风化岩地表，导致燕山等区域出现连续灰色台面，绿色山体像另贴在上面。本轮在已有山地分类下，结合已归档的2017生态区资料选择代表性下层底色：温带草地、亚热带腐殖质或干草原。原有风化岩材料继续覆盖在上层；丘陵与山地分别采用0.28、0.50的绘制透明度，并在邻格之间连续过渡。

这两个数字是插画透明度，**不是实测裸岩比例**。生态区只约束区域材料选择，不证明某年某格有草地或森林；本轮不新增树木、农田、土地利用、水系或通行属性。没有相应来源、峰顶及其他生态类型继续采用原策略。山体独立原图的下缘柔和区由12%扩大到24%，仍引用完整原图。

## 绘制批处理

地形淡色与山体投影由每格独立绘制改为分区缓存的三角网，保留每个来源格的中心、半径、颜色和透明度渐变。等高线按原始端点生成窄绘制带，再用着色器抗锯齿；源线段不平滑、不移动、不增加。切换地图会清空缓存，缩放时重建等高线屏幕宽度，拖动复用已生成的分区。

新测试覆盖来源格保持、负坐标、长线段跨区、四档缩放宽度、空地图清理、战略显示层次、两层绘制顺序与海岸裁切。9组组件检查共507项通过，见[执行清单](../reports/relief_grounding_v0232/final_components_01/runs.json)、[山地下层检查](../reports/relief_grounding_v0232/component_tests.json)和[批处理检查](../reports/relief_grounding_v0232/batching_tests.json)。

## 实际性能范围

开发引擎在RTX3060、1920×1080、京奉真实地图的同一相机路径测量，关闭垂直同步和帧数上限。最后一轮开启底材的两个180帧样本平均95.78、99.12 FPS，但95分位帧耗时仍为106.85、102.44毫秒，最大176.86、159.90毫秒。**缓存重绘尖峰仍会造成可感知卡顿，不能用平均帧率宣布流畅达标。**

前期地形阴影批处理的开发试验把绘制调用峰值从约16,275降到约6,791；加入等高线网格后的最终开发试验峰值约6,820，没有证明这一项进一步降低了总绘制调用或尖峰。它们来自不同的开发阶段，不能冒充两个发布版本的严格性能对照。

最早试验与自己的无界面测试有重叠；第二次试验未控制其他应用负载，其旧字段只表示自己的测试工作进程。原始报告保持不变，解释见[测量范围](../reports/relief_grounding_v0232/pan_cost_trials.md)。最后一轮启动前没有检测到其他Godot进程，但仍未控制全部后台CPU/GPU负载；所有样本均为桌面开发引擎，不构成Android实测。完整帧样本与环境见[最终开发试验](../reports/relief_grounding_v0232/contour_mesh_native_01/pan_cost.json)。

## 历史、音乐与剩余范围

[源码范围检查](../reports/relief_grounding_v0232/scope.json)确认158份受保护规则、地图、剧本、持久化与表现数据文件相对0.2.31提交保持原字节；内容注册器仅更新版本号。素材清单和来源索引也保持原字节。这只能证明本次渲染修订没有改动既有内容，不证明既有历史问题已经修正。

后续配乐继续使用用户指定的 **music-gen-remote-YuE2**，经原生Windows调度远端RTX3080，以无台词、无歌词纯器乐为主。本轮没有生成或替换配乐，现有本地曲目的真实来源保留。

山体仍有重复与独立图符感，武汉边缘留白、大片冲积土、粗折线河道与有据支流补充仍需处理。全兵种完整方向动作、亚洲历史起局、将领具体部署以及Motorola X30物理安装、触摸、GPU、发热与续航尚未全部完成。设计图、美术批准、自动检查与物理验收分别记录。
