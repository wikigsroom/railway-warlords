# 0.2.34 局部战区五倍比例与独立江岸

本轮修复汉口、宁浦两张局部地图的比例与取景问题。两图的真实经纬度范围、投影和已复核的陆地轮廓保留；每格地理半径从1,250米细化为250米，操作蜂窝的世界坐标半径仍为48。相同地理距离在画面中放大5倍，近景能够呈现城市与江岸之间的空间，三镇和两岸全景则通过缩小地图查看。

当前状态：同一源码身份的Windows与签名Android/code39已导出并核验，完整30组、14,585项回归完成依赖字节封存；207项独立聚落/控制几何、86项局部规则、122项来源/范围、773项原生HUD输入、106项正式地图布局和48项GPU检查通过。13个地图视口及菜单/冒烟/山地共16张最终程序整幅图已逐张查看；APK核对双架构、签名、2,509张贴图及3首既有配乐。这是一版局部地图可玩测试交付，整体《欧陆战争6》品质、商业美术与物理X30验收仍未完成。

边缘补格数量随分辨率变化，因此格数不能直接宣称为旧版的25倍。操作区域以真实编制范围限制，范围外的补格不开放行军。京津、京奉、中国东部和亚洲战略层本轮不重新划定地图。

绘制诊断已改为读取地格实际高程来源标记，不再根据陆地轮廓来源误报提供方。两图使用92,120个实际坐标采样点，每格包含中心和四个半格半径方向点。数据来自OpenTopoData提供的SRTM v3 90米数据集；每次请求、原始响应和SHA256均保留，922次原始响应逐份核验。来源说明见[数据集文档](https://www.opentopodata.org/datasets/srtm/)与[API文档](https://www.opentopodata.org/api/)。这是一份现代雷达高程物理参考，不是1924年的地表、植被或土地利用调查。

原响应有12个负值样本，其中3个是宁浦格中心的−1米或−2米值。对涉及坐标另取30米SRTM交叉参考后，仍不足以证明这些位置具有可靠的真实负高程地貌。原始数值完整保留；涉及这些支撑点的10格加上质量标记，不用于推断凹地阴影或等高线，点选时显示“高程采样待复核”。[USGS的任务说明](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-digital-elevation-srtm-mission-summary?qt-science_center_objects=0)给出90%置信度下16米的绝对垂直精度任务指标，该指标不能当作每格精度保证，也不能用来证明单个负值正确。

## 河流、城市与码头

主河道的操作水格与绘制中心线统一取自同一批HydroRIVERS来源河段，汉口15段、宁浦16段，采用6级及以上的来源干流。它替换旧局部图中粗粒度的主河道参考；不自行连接断开的河段，不杜撰支流名称。更细支流仍遵循既有来源筛选与缩放层级。河宽是战术画面符号，不作为对应年代河岸的测量值。

旧逻辑为港口功能将城市格吸附到岸边，细化后会把南京等城市移到距离原参考点数公里的位置。本轮将城市中心与港口功能拆开：城市中心保留原经纬度、年代名称与行政归属；码头使用同岸可达的岸边陆格及相邻来源水格。舰艇在码头水侧部署，补给和上下船使用码头，普通城市征募仍使用城内格。

五个城市格距原有近似参考点为121—244米。这只是相对工程内参考点的操作格偏移量，不能解释为历史城址测绘精度。港口的岸边位置也属于同岸通达的战术抽象，不宣称精确还原历史码头。浦口与下关的渡运联系已有1924年前史料支持，例如[南京官方纪念资料中的1918年渡江记述](https://yht.nanjing.gov.cn/rednanjing/hsbb/202506/t20250618_5589089.html)；游戏渡口仍不计作铁路桥，不将1930年代的铁路轮渡能力提前使用。

江岸标记引用现有完整独立素材，通过原生Godot绘制；没有新增、裁取、补绘或拼接PNG。码头名称、城市名称与编队模型使用同一套避让排版。区域控制色继续保留半透明叠加，地表细节独立可见。

## 两张局部图的游玩入口

主菜单进入“军团挑战”，选择“江防护航”（汉口江段）或“跨江登陆”（南京—浦口）。这两项采用标准化预算与部署，属于战术演练。开始后打开目标面板，查看需要保全的编队及实际江岸目的地；缩小地图可以同时看见两岸或武汉三镇。

1. 点选城市或带名称的江岸标记，可查看所属城市。城内征募普通陆军，港口舰艇则在江岸附近的合法水格出队；有单位占位时，队列会按部署规则寻找可用位置。
2. 手动装船时，先把步兵等可装载陆军移至本方未封锁港口附近的陆格，让运输船停在相邻水格。选中陆军，在更多命令中选择“装载到运输船”，再选择本方运输船；总装载容量为3层。
3. 新执行装船会结束运输船与乘员本阶段行动，乘员下一己方阶段才可卸载。选中载员运输船，使用“卸载”并点选可见、空闲、相邻的本方港口陆格，然后确认命令。范围外格、敌方港口和封锁港口会被拒绝。
4. “跨江登陆”开局已有载员，需先驾驶运输船航行，再在目标江岸附近实际卸载。“江防护航”则需让目标舰艇抵达指定江岸的一格范围，并保全目标编队。全部阵营结束各自阶段后，对局日期推进一天。

## 重建入口与追溯

一次性迁移脚本为[refine_local_maps.py](../tools/refine_local_maps.py)，按`prepare`、`fetch`、`compile`、独立地理核验、`install`执行。原始地图和所有派生目录先备份到原工作区`output/local-map-refinement-v0234/`。该脚本要求迁移前源文件身份匹配，安装后不能再把当前地图当成旧图重复迁移。

[refresh_local_map_presentation.py](../tools/refresh_local_map_presentation.py)重投影两图的聚落与控制区，并依次重建河流、表面区域、地形材质和连续底材。其`--resume`只接受已记录为终止失败、且地图SHA未变化的任务。其他四图的聚落输入与底材分配先逐项比较，沿岸网格仅在该图输入数值完全不变时重绑容器来源SHA；这不冒充新的几何测绘。

独立检查发现，三张沿海地图的旧控制区仍沿用细海岸重建前的裁切输入，导致局部漏色；旧检查器也未跟随运行时实际采用的沿岸控制网格。本轮让检查器严格核对当前海岸网格及其地图、聚落SHA，并按当前真实陆地、年代省界与既有城市点重新生成城市影响区。陆地、海岸、行政边界和城市坐标数值不变；变更仅限三个海岸网格的控制三角形。207项检查以原有容差通过，修复前的失败报告与网格另存。影响区属于玩法控制抽象，不宣称精确历史军事边界。入口为[refresh_coastal_control.py](../tools/refresh_coastal_control.py)。

旧`compile_maps.py`整包入口早于亚洲图与细岸线，只能用于历史初始构建。本轮增加防护，检测到当前亚洲图或250米局部图时拒绝覆盖；其`compile_map`导入函数继续支持专用编译器。

可移植来源副本、基线与核验清单见[来源目录](geography-provenance/local-map-refinement-v0234/README.md)。原始高程响应另存为无损ZIP，SHA256为`bafd9ec4800566369c42ddbfd86679eb68d593a5667ca5707068ccf6a4da6a04`。地理来源登记表保留旧高程来源，并追加本次采样集和HydroRIVERS来源记录，不改写原始数据的年代或授权。

## 验收边界

独立地理预安装核验包含922份原始响应身份及31项坐标、来源与城市核验，共953项；这些不是953项玩法检查。原生规则检查另外验证两张地图双方的默认部署、岸边舰艇生产、港口补给及实际移动、上下船命令。移除其他部队的导航夹具只能证明路线和目标可达，不证明完整AI战斗平衡。补给回归保留原始0.2.2 Dijkstra夹具，只在独立副本中将两处港口坐标读取改为显式岸边坐标；检查器断言该副本与旧源码仅有这两处替换，普通城市补给起点仍在城市中心。旧算法与新优化算法继续逐格比较补给距离、海军连通分量及完整资源、部队和事件结果，不把新的港口规则伪称为旧版行为不变。

目前开发引擎的13个完整原生视口已逐张查看，93项布局与身份检查通过；这批属于江岸名称修正和沿海控制区重建之前的开发证据，保留其真实身份。当前接入地图的86项原生规则检查通过，包含双方上下船、敌方及封锁港口拒绝、城市生产与补给。

最终程序的汉口/武昌/汉阳近景、三镇与区域总览、南京/宁浦江岸/总览、桌面X30尺寸、大字、北京、海岸、山村13张地图，以及菜单、界面冒烟、山地3张均已完整查看；见[查看记录](../reports/local_map_refinement/visual_review.json)。来源诊断与双端身份统一为本轮最终源码。桌面尺寸模拟不等于物理X30验收。完整兵种动作、逐人能力平衡、全部亚洲历史开局和商业美术仍独立待验。大字总览中武昌地名与比例尺局部重叠，底材重复、河道折线和简化建筑也仍待处理；这些画面缺口未以自动检查通过结案。
