# 亚洲战役系统与自由世界

版本：0.2.7。运行入口仍是 Godot 主场景；内容入口是 `content/scenarios/`。

## 两种玩法

| 模式 | 入口 | 目标 | 历史约束 |
|---|---|---|---|
| 历史战役 | 21 个 `campaign_1840/1860/1890/1900/1917/1927/1940_*` | 消灭指定编队、夺取/守住城市、俘获将领、修复铁路、护送或在期限内生存 | 任务 `province_scope` 最多三个省级/地区名称，目标城市使用真实坐标；“夺取”任务不会从玩家已占目标城起步，守城/解围任务使用 hold 目标 |
| 自由世界 | 7 个 `asia_1840` 至 `asia_1940` | 统一战略节点或期限积分 | 起局控制来自真实时间锚，玩家之后可以改变外交、占领和经济 |

每次任务的 `objective_design` 显式列出成功与失败条件；`VictoryRules` 只根据规则状态结算，不根据 UI 点击或演示帧。

任务制作规则：
- 一个任务只处理一条可读战线；省级范围不超过三项。跨省冲突拆为不同任务，不把整场战争塞进一关。
- 真实地点作为目标，战术部署采用邻近六边格；“编队 stack”是玩法单位，不声称等于历史营/团的原始编制。
- `destroy_named_formation`、`capture_named_commander_if_present`、`capture_or_hold_strategic_city`、`protect_supply_line` 等条件可以组合，但胜利必须能通过可见战报验证。
- `destroy` 任务在起局时把敌方部署的单位绑定到 `destroy_formation_id`，运行时追踪真实 unit id；目标编队全部被击溃后才记为完成。`capture_commander` 任务追踪将领的受伤、撤离或转归玩家，`optional_if_absent` 只允许来源明确写出“在场时”的条件，避免空目标自动胜利。
- 任务初始控制可与自由世界同一地图不同：战役会将目标城、基地城和敌方基点限定在编排范围，避免把全亚洲的所有部队挤在一关。

## 自由世界回合流程

1. 选择时间锚和阵营。只有在该时间锚拥有至少一个二级以上城市/战略节点的阵营进入可玩列表。
2. 玩家先行动；回合推进由场景 `days_per_round` 决定。1840/1860/1890/1900/1917/1927/1940 起局拥有不同城市控制和初始敌对关系。
3. 本方阶段依次处理：事件与天气 → 疲劳/合法性/殖民影响 → 城市收入与补员 → 征募/建设/铁路维修 → 外交援助 → 补给分配 → 将领刷新 → 视野。
4. 单位可移动、攻击、使用战法、补给、修铁路、铁路投送、装卸船；攻击使用可保存的随机骰流，并在战报中记录攻击骰、防守骰、修正值、反击和伤害。
5. 阵营灭亡条件是失去所有关键城市且没有可进行战略反击的占领单位；同盟通过关系图合并结算，但敌对关系会拆开胜利集团。
6. 期限结束按关键城市、城市经济和幸存兵力积分；自由世界允许多个阵营以同盟成员组获胜。

## 外交和多阵营冲突

- `declare_war` 消耗战争令并立即把关系设为 WAR；`truce`、`alliance`、通行权、补给权、援助和贸易都写入关系状态。
- 初始关系由场景数据登记：例如 1840 清—英/英属印度、1860 清—英法、1900 清/义和团—八国、1917 北洋—护法、1927 国民革命军—直奉、1940 中国战区—日本占领区。
- 盟友不自动共享城市所有权；共享胜利只在 `alliance_groups` 中按关键城市和敌对关系结算。
- 殖民影响来自港口控制和贸易走廊，是游戏变量，不等于史实殖民人口或税收数字；合法性/疲劳也只用于玩法。

## 任务设计的真实地理映射

- 华北战线使用北京、天津、保定、石家庄、济南、青岛、奉天、旅顺、哈尔滨等真实节点。
- 长江和东南战线使用上海、南京、镇江/苏州、杭州、宁波、汉口、武昌、宜昌、长沙、南昌等真实节点。
- 西南与边疆使用广州、南宁、昆明、贵阳、成都、重庆、拉萨、兰州、迪化、喀什噶尔等真实节点。
- 亚洲外线使用东京、大阪、首尔、平壤、釜山、海参崴、莫斯科、彼得格勒、德黑兰、喀布尔、德里、加尔各答、仰光、曼谷、河内、西贡、新加坡、马尼拉、巴达维亚等真实地名。
- 地图底图只表示物理陆地、水体和河流；战役的历史省级范围写在任务 JSON，而不是用无来源的现代行政多边形覆盖亚洲。

## 与欧陆战争式体验的对应

- 城市是资源、征募、机场、车站和胜利节点；道路/铁路是移动与补给的可见战略网络。
- 每个单位有行动点、射程、弹药、压制、士气、经验、将领和补给状态；攻击有克制矩阵、地形防御、掩体、反击和随机骰子。
- 动效由真实命令事件驱动：路径行军、转向、炮击弹道、受击闪白、阵亡、反击、航空侦察/轰炸、占领和骰面窗口均来自当前状态。
- UI 用钢灰/黄铜框、层级势力色、地名和控制图例保持《欧陆战争6》式一眼可读，但所有图像都来自项目已批准的 Sub2 路线或 Godot 程序绘制。

## 运行验收

- `tests/asia_content_test.gd` 检查 7 个时间锚、81 城市的七份控制记录、30 个编制、19 个历史来源、21 场战役和全部省级范围上限；同时验证所有城市归属能解析到起局阵营，并用 1940 百团大战交通线任务演练“消灭目标编队”胜利判定。
- 亚洲状态构建检查已经并入正式 `asia_content_test.gd`；不再把临时准备脚本当作史实证据。
- 桌面原生截图使用 `-- --scenario asia_1840 --capture --capture-path ...`，自定义参数放在 Godot 的 `--` 之后；元数据不会把亚洲地图强行索引到旧 1924 聚落表。
- Motorola X30 已作为 2400×1080、移动 UI 1.2 倍的工程测试目标；未连接实机时不把桌面模拟布局写成触控/温度/续航验收。
