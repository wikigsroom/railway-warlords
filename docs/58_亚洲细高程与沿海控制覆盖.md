# 0.2.36开发预览：亚洲细高程与沿海控制覆盖

本轮继续改善《欧陆战争6》对照中最明显的地图问题：亚洲战略图缺少连续山势，日本等狭长陆地缺少细高程明暗，部分沿海陆地又因规则格中心在海上而漏掉控制色。修订使用有来源的数值高程和已有陆地几何，保持原来的操作蜂窝、城市、历史定义与游戏规则。

这是**开发预览**，不是整体美术达标或物理Motorola X30验收。0.2.35/code40的完整发布归档保持不变；0.2.36/code41在独立的原生Windows目录构建和验证。导出、回归与最终程序画面的实际结果分别保存，不使用旧版本截图充当新版证据。

## 地形显示为什么需要调整

此前的连续高程依赖相邻粗规则格组成三角形。亚洲战略图中，日本岛屿等地区即使有准确的岸线，也可能凑不齐相邻陆地格，因而缺少连续山脊。直接放大山体符号不能修复这个问题，还会放大重复贴图。

本轮增加独立的数值高程场，直接复用105,401个顶点、81,193个三角形的已有陆地网格。高程照明沿真实陆地与已有湖泊空洞裁切，覆盖条件不再依赖三个相邻陆地格。山体符号仍来自既有独立Sub2原图；没有通过裁图、拼接或重绘生产新美术。

原始高程来自[Tilezen Terrain Tiles公共数据登记](https://registry.opendata.aws/terrain-tiles/)；格式依据[Joerd官方GeoTIFF说明](https://github.com/tilezen/joerd/blob/master/docs/formats.md)。共64张zoom4科学GeoTIFF，来源URL及原始文件SHA256随编译记录保存。它们是科学测量数据输入，不作为生成美术或游戏截图使用。已有[地理资料许可说明](../assets/legal/GEOGRAPHIC-DATA-NOTICES.txt)继续随游戏打包。

| 项目 | 实际口径 |
|---|---|
| 范围 | 东经20°—180°、南纬10°—北纬80° |
| 数值表 | 3,201×1,801，共5,765,001个重采样节点 |
| 表格间隔 | 经、纬各0.05°；不是新增的独立实测点 |
| 源数据 | Web Mercator / EPSG:3857，投影像素约4,891.97米，地面尺度随纬度变化 |
| 编码 | 有符号16位整数米，gzip/base64，JSON为数值表 |
| 舍入误差 | 对原始高程双线性采样的整数舍入不超过0.5米；不代表真实地形绝对精度 |
| 查找表载荷 | 11,530,002字节，运行时建立RG8数值纹理 |
| 东侧180°边界 | 源数据边缘采用单侧取样，位移不超过一个源像素，编译记录明确保留 |

北西方向光照结合邻近与较大范围坡度；平缓低地保持安静，较大的连续山势可穿过细长岛屿。高程在运行时先偏移至无符号范围，再交给GPU线性插值，避免海拔跨零时二进制字节插值产生虚假高墙。纹理使用线性数值通道，正确对齐节点的纹素中心。

资料保留粗分辨率的限制：这里不声称显示精确峰顶高度、历史植被、十九世纪河道或逐年的地表调查。规则格的通行、地形防御、补给、海陆分类和城市坐标均使用原登记数据。

## 沿海控制色补齐

原亚洲控制层按规则格中心的海陆类型筛选，导致格心在海上、实际有岛屿或半岛陆地的格子完全漏色。本轮离线补齐915格、48,181个三角形；其中831格的中心在源陆地之外。新增文件只保存几何，没有添加阵营、历史边界或虚构城市。

运行时仍使用当前战局中已有城市的归属与影响范围决定控制色。填色继续半透明，并按同一来源陆地与水洞裁切；不同归属区域之间才画政治共边。补齐绘制不把规则水格改成陆格，也不扩大可移动范围。

1927年普通原生画面的诊断记录中，561个补充格获得现有规则的控制色，包含20个日本主要区域沿海碎片。远离既有城市影响的土地继续沿用原来的无归属显示。这个图层表示**游戏中的控制影响**，不能作为真实历史军事前线或精确领土测绘。

独立GEOS审查逐格核对915格、48,181个三角形与原生float32源陆地。最大对称差面积约0.025523世界平方单位；按原生舍入所需的0.002世界单位边缘带检查，带外填充及边线长度均为零。该舍入带是几何核验容差，不是允许新增陆地。

RTX3060、Windows、1920×1080、OpenGL兼容渲染下，实际EXE在亚洲1927静止战场采样180帧，60帧上限时平均59.985FPS、95分位18.039毫秒，见[观察回执](../reports/geographic_relief_v0236/exported_windows/benchmark01/validation.json)。当时本轮导出和全量回归已经结束，但其他桌面应用未统一控制；这是单次静止观察，不是平移、战斗或Android性能验收，也没有与旧版做性能优劣比较。

身份口径：导出回执使用“按文件名排序的运行文件SHA256映射，再对规范JSON计算SHA256”，与旧版线性拼接的source_digest是不同算法。原始素材采用本轮完整副本校验记录，代码和数据重新校验，导出过程中再次检查被触及的文件；不把不同算法的摘要混称为同一个源码哈希。

## 保留失败尝试

早期大阪01虽然正常退出，但地图整数／浮点数组比较使新高程场没有启用，画面与基线相同。这次尝试**不算视觉验收通过**。修复后专项加载实际归一化地图，截图控制器必须同时核对高程场启用、GPU纹理存在和实际着色器开关，不能只根据进程退出码判定。

控制层02出现4项失败，原因是专项在HUD隐藏缩略图后仍按旧缩略图位置抽样，实际取到了主地图。现在只在缩略图可见时比较其像素，隐藏时明确记为跳过；主视口水面检查保留。大阪03曾因新全局类未完成引擎注册而解析失败；重新导入后才生成后续有效证据。原失败日志、画面和中间版本保留，不用最终通过结果覆盖它们。

## 对照《欧陆战争6》仍未完成的内容

- 连续高程使日本和喜马拉雅山势更清楚，但大面积底纹仍有相近色带、粗格边界与明显材质分区。
- 独立山体与地貌符号仍有重复、比例偏大和疏密不均；连续阴影不能替代后续完整素材深化。

- 未完成物理X30验收、商业级整体美术验收及长期人工平衡，不以检查数量或素材总量冒充完成比例。

本章只记录这轮具体修复和可复查的边界；整个质量目标继续推进。
