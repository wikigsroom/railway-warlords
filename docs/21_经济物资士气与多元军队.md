# 亚洲全境经济、物资、士气与多元军队

版本：0.2.7。所有数值先服务于可玩性；历史史料中的兵力范围与游戏资源量严格分开。

## 资源与回合公式

| 资源/指标 | 来源或消耗 | 玩法作用 | 史实标记 |
|---|---|---|---|
| 军费 cash | 城市收入、贸易、援助；征募、军饷、建设、维修 | 维持军队与城市 | 游戏货币，不等于某国财政报表 |
| 粮秣 food | 城市/粮仓收入；部队补给与军饷 | 影响补给状态、行动和恢复 | 游戏资源，不替代史料粮秣吨数 |
| 军备 arms | 城市工业/兵工收入；征募、补员、炮弹、维修 | 限制火力与扩军 | 游戏资源，不等于历史枪炮库存 |
| 燃油 fuel | 港口 4、车站 1 的每阶段基础产出 | 1940/1927 交通和机动的压力指标 | 游戏变量；1840/1860 不把它解释成石油产量 |
| 白银 silver | 二级以上城市 3、普通城市 1 的每阶段基础产出 | 贸易与外交的长期储备 | 游戏变量，不能当作史实货币总量 |
| 兵源 recruit_reserve | 城市等级、粮仓和每阶段恢复 | 决定能否把经济转换成编队 | 游戏人口抽象 |
| war_exhaustion | 交战每本方阶段 +2，和平阶段 −1，0—100 | 影响收入和高疲劳士气 | 游戏压力指标 |
| legitimacy | 交战 −1，和平 +1，0—100 | 与疲劳共同影响收入 | 政治玩法抽象，不代表档案调查 |
| colonial_influence | 本方港口每阶段累计 | 贸易/外交与殖民势力玩法 | 游戏指标，不等于殖民疆域 |

收入惩罚采用 `income_penalty_permille = clamp(1000 − 3×war_exhaustion + 2×(legitimacy−50), 550, 1100)`。本方阶段先计算压力，再收税、发军饷、分配补给；欠饷会降低编队士气。疲劳达到 70 后每阶段额外降低本方部队士气。

## 补给、铁路与城市

- 城市等级 1—3 拥有不同收入、城防和兵源上限；兵营、兵工厂、车站、港口、补给站、医院、工事、电报、市场和粮仓通过队列建设。
- 铁路边有容量和损坏状态。工兵修复后才可恢复军运；铁路投送消耗运力/燃油抽象并保留一次性行动约束。
- 补给路径受城市、铁路、道路、海/河移动域和外交通行权影响；断路会使 `supply_state` 降级，降低行动、攻击和士气。
- 港口不自动拥有周围土地；城市占领和港口通行是两件事，适用于租借地、殖民港和战区。

## 年代兵种闸门

亚洲场景的 `equipment_whitelist` 与单位的 `historical_era_min` 同时生效，命令层再次校验当前日期；编辑器不能通过改 UI 直接征募超时代装备。

| 最早年代 | Godot 兵种类 | 映射说明 |
|---:|---|---|
| 1840 | 地方守备队、步兵团、骑兵团、工兵营、野战炮营、沿海炮舰、运输船 | 以绿营、地方勇营、骑兵、炮台/舰队分遣队的战略抽象表示 |
| 1860 | 以上 + 江防炮艇 | 表示蒸汽河运/江防，仍不自动等于某一艘历史炮舰 |
| 1890 | 以上 + 机枪营 | 以甲午前后新式火器和机枪类火力作为时代闸门 |
| 1900 | 以上 + 重炮营、装甲列车 | 可用于联军/铁路战区；编队数量仍由 OOB 范围约束 |
| 1917 | 以上 + 突击营、装甲汽车队 | 反映第一次世界大战后编制变化和军阀交通战 |
| 1927/1940 | 全部以上 | 1940 的占领、国军、八路军、殖民军可使用完整交通/火力层 |

兵种规则：
- 步兵可占领城市；机枪营有较高压制与反击；骑兵有更高行动点；炮兵远射但不能占领；工兵修铁路/工事；装甲汽车有高机动；装甲列车依赖铁路；炮艇/运输船/炮舰按河流或海域域移动。
- `stack` 是可读战斗编队层数；不能直接翻译成一个历史营、团或旅。真实部队名称和兵力范围只在 OOB 表中显示。
- 克制矩阵、地形掩护、血量、压制、士气、弹药和反击在 `combat_rules.gd` 计算；攻击骰使用保存的 Park–Miller 流，预览只显示区间，实际结算记录两枚骰。

## 士气、经验与将领

- 基础士气 50，断粮、受击、将领受伤和友军被击溃会降低；占城、击破编队、补给完整和待机筑垒会提高或缓慢恢复。
- 将领有被动/主动战法、星级、经验和编队绑定；将领阵亡/受伤会写入战报。未能找到可靠的历史指挥官时，OOB 使用 `unknown_*`，不会用生成名字冒充史实。
- 养成档案可升级科技、将领、战法和勋章；挑战模式使用标准化快照，避免把成长数值误写成历史战力。

## 经济与外交循环示例

1. 1840 玩家选择清帝国：先保住广州—福州—宁波—上海的港口与内河粮运，利用外交拖延俄国/英属印度，处理清—英战争疲劳。
2. 1860 玩家选择太平天国：南京—苏州—杭州是高价值但高压力的连续城市，湘军与英法北线是不同关系，港口和长江运输决定补给。
3. 1900 玩家选择八国联军：天津港、铁路和北京救援是核心；玩家不能把 20,000 人级救援纵队和后续占领部队合为一个 stack。
4. 1927 玩家选择国民革命军：以武汉、长沙、南昌、南京/上海方向的铁路和补员维持北伐，必须处理与直系、奉系、晋系和地方势力的外交。
5. 1940 玩家选择国军/共产党/日本占领区/殖民阵营：燃油、铁路、港口和机场决定机动；中国战区和印度支那战区可以因外交而分离。

## 数值证据和限制

- 场景起始现金、粮食、军备、燃油、白银写在每个 JSON 的 `starting_resources`；这些数值是平衡基线，不宣称历史财政统计。
- 30 个 OOB 编制的兵力范围来自来源表且保留 `strength_status`；发布前若需要精确到旅/团/营，必须新增来源 ID、日期、编制口径和版本化数据，不可直接把范围改成单点。
- 战役目标的“命名编队”只把 OOB 编号绑定到若干可部署 stack，再由战斗结果判定全歼；它不会把一组游戏 stack 虚称成档案中的一个营、团或旅。将领俘获同样使用受伤/撤离状态作为可审计的游戏结果。
- 双端目标是 Windows x86_64 和 Android ARM64/ARMv7；X30 只记录桌面移动布局目标，实机安装/触控/温度/续航仍单独验收。
