# 开发工具与发行检查 · 0.2.7

`tools/developer_tools.py` 是本工程的只读开发诊断入口。它读取 Godot 实际使用的定义表、地图、剧本、回放日志、AI报告和 `assets/manifest.json`，不修改内容、存档或栅格图片。所有子命令支持 `--out` 保存 JSON；没有通过工具输出强行把历史、美术或平衡状态改成已审核。

| 工具 | 命令 | 当前证据 |
|---|---|---|
| ScenarioInspector | `python tools/developer_tools.py scenario conq_1924 --out reports/developer_scenario_conq_1924.json` | 1924征服的地图、势力、事件、来源和部署状态 |
| HexInspector | `python tools/developer_tools.py hex conquest_china --cell c_0_254 --out reports/developer_hex_first_cell.json` | 蜂窝坐标、六邻接、城市、铁路节点、地理来源 |
| CommandLog | `python tools/developer_tools.py log --type Attack --limit 5 --out reports/developer_command_log_attack.json` | 100回合长局的真实命令、版本、骰流和事件指纹 |
| BalanceRunner | `python tools/developer_tools.py balance --out reports/developer_balance_matrix.json` | 72短局 + 6完整征服的实际 AI 报告汇总与人工复核项 |
| AssetValidator | `python tools/developer_tools.py assets --out reports/developer_asset_validation.json` | 238项当前 PNG 的存在性、源 SHA 和审核状态 |
| HistoricalReleaseChecker | `python tools/developer_tools.py history --out reports/developer_historical_release_check.json` | 33个场景的来源链接、地图资料和历史发行状态 |
| DeveloperToolsSmoke | `python tools/developer_tools.py smoke --out reports/developer_tools_smoke.json` | 串行调用以上六类诊断并确认当前工程数据链闭合 |

## 当前结果

ScenarioInspector 确认 `conq_1924` 使用 74,762 格的东部中国真实地理抽象、55 个功能城市、36 个铁路节点和 32 条铁路边，势力定义全部存在；北京政变事件有条件日期和来源。它同时明确记录“城外编队与能力白名单为平衡配置”。

HexInspector 对每个被查询格返回真实蜂窝位置、六邻接、地形、城市/铁路节点和来源说明。它把 `restricted` 格和地图边缘显示出来，避免调试工具把图幅外格误看成可通行区域。

CommandLog 当前从 100 回合 QA 长局读取 3,171 条命令；其中真实 Attack 命令 208 条，预览版本、事件 SHA 和 CombatRandom 状态随行记录。工具只读日志，不重放或重写战局。

BalanceRunner 汇总短局 72 例、318 回合、11,535 命令和完整征服 6 例、425 回合、19,038 命令，均为 0 拒绝。25 个胜负/提前结束样本被列为人工策略或难度复核项；这不把自动 AI 通过误认为人工平衡完成。

AssetValidator 当前 238/238 项源 SHA 一致、0 个文件错误；所有项目仍是 `generated_pending_visual_review`。其中包含16个兵种族的64张北/东/南/西独立朝向源图，仍保留设计章要求的逐项轮廓、缩小可读性、年代装备和美术统一性审核边界。

HistoricalReleaseChecker 当前 33/33 个场景的来源链接可解析、0 个缺失来源 ID，但 33 个场景均为 `pending_manual_historical_release`。原因是剧本仍包含明确标记的 authored tactical deployment，历史省界/自然地理来源不等于军事起局、人物归属、装备白名单或县界发布核验。

DeveloperToolsSmoke 当前通过：场景、蜂窝、命令日志、AI报告、素材清单和历史来源六类诊断均能从当前工程读取并产出报告；它只证明工具链数据闭合，仍保留素材视觉、历史发布、人工平衡和设备验收的未完成状态。

## 双端导出证据

`tools/verify_exports.py` 已完成当前 Windows/Android 导出复核：Windows 原生视口与 UI 场景通过；0.2.7 APK 的签名 v2/v3、`org.railwaywarlords.game`、versionCode 12、SDK 24–36、无额外权限、`arm64-v8a`/`armeabi-v7a` 双 ABI、亚洲战略地图与既有数据字节均通过。`reports/android_devices.log` 仍只有 ADB 标题行，表示当前没有连接 Motorola X30；它不能替代物理安装、触控和持续性能验收。

本轮补充包还封存 `delivery_preflight.json`、`apk_content_validation.json`、`export_results.json` 和 `android_devices.log`，让双端结果可独立复核。已封存的 0.2.6 发布包不因后续文档补件重写，0.2.7 的亚洲时间线、战役、编制和资源诊断随当前包提供。

## 发行规则

工具输出可进入审计包，但不能替代 Godot 原生测试、导出验证、100 回合存档回放、物理 Android 设备验收或人工历史/策略评审。任何要把 `content_status`、`review_state` 或 `historical_deployment_release` 改为发行状态的变更，都必须同时补充来源、人工签核和新的内容指纹；当前 0.2.6 双端成品保持原 SHA，0.2.7 以独立内容指纹和导出 SHA 交付。
