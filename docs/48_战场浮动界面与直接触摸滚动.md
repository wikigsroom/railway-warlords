# 0.2.30 · 战场浮动界面与直接触摸滚动

本版调整战场布局、局部地图开场取景与触摸滚动。它是可操作界面的迭代，不代表整套美术已达到《欧陆战争6》的商业水准。历史起始状态、兵种完整动作、山脚和河岸等尚未完成的工作，继续按各自状态保留。

## 与参考战场的对应关系

复看[《欧陆战争6：1914》官方战场画面](https://ew6w.ieasytech.com/assets/image/manual/en/27.jpg)，可见地图占据视口主体，资源置于上缘，操作集中在边缘。本轮参考的是这种信息层级；官方图片仅作研究，不作为游戏素材。

此前版本的常驻任务板、图例、侧栏、完整检查器与横贯屏幕的底栏，同时压缩了地图。现在资源与日期合成一条短顶栏，选中编队摘要置于左下，主要命令浮动于右下，工具位于右上边缘。

| 入口 | 实际行为 |
|---|---|
| 左下编队／城市／地块摘要 | 展开现有详细档案，使用实际人物年代肖像与规则数值 |
| 作战目标 | 展开实时目标与进度；护送任务列出受保护编队、实际目的地与一格范围 |
| 图层 | 分别切换势力、地形、地名、铁路、补给与蜂窝；明确显示开／关 |
| 军令 | 自动作战、撤销移动、侦看地块与地名、外交援助 |
| 己方城市 | 主命令直接显示征募、建设、修复城防、待命部队和结束回合 |
| 设置／战报／全图 | 沿用实际暂停、日志与战略地图功能 |

详情、目标、图层和军令面板互斥展开，Escape先关闭展开面板。攻击／移动确认、命令条件检查、演出期间的自动作战和跳过功能沿用现有规则入口。

## 地图处理的具体范围

汉口小地图原先在低缩放下呈现为大块空白背景中的窄矩形。开场缩放现根据已有`render_extent`与可用视口取景，保留原来的缩小、平移和全图入口。这是相机调整，没有放大地理比例、改变蜂窝尺寸或扩张地图。

底纹分配补上实际源陆地内部判定：完全落在多边形外的矩形不会穿过边线，旧的“未穿过边界”检查会错误接受它。汉口因此移除9处越界分配，保留250处安全分配。已有纹理选择、原始PNG、真实地理、规则单元及随机流没有因该修复改写。

界面图例按需显示不改变控制层透明度：局部控制填充仍为0.26，大尺度控制场仍为0.21。色块表达当前战局控制，不等同于已经考证的历史军事边界。

## 直接触摸滚动

项目关闭触摸转鼠标，以便地图直接处理单指选取、拖动和双指缩放。检查[Godot 4.7滚动容器实现](https://github.com/godotengine/godot/blob/4.7-stable/scene/gui/scroll_container.cpp)后，确认其拖动路径仍依赖鼠标事件。本轮新增`TouchScroll`，直接接收真实控件命中后的触摸与拖动事件，应用于共用滚动列及独立将领身份栏。

超过滑动阈值后，组件通知子控件开始滚动，以取消按钮的待执行点按。松手结束滚动，普通鼠标滚轮、键盘焦点和原生滚动条继续使用引擎行为。未新增全局触摸转鼠标，也未向地图重复发送鼠标事件。

独立组件回归涵盖：从按钮上起滑、滚动到末尾、滑动不触发命令、随后点按只执行一次、不截获外部控件、隐藏面板清理触点，以及鼠标滚轮继续工作。组件夹具不作为游戏实机截图。

## 选中对象摘要刷新

最终复查发现摘要缓存遗漏城防当前值／上限、部队兵力上限与兵种定义。数值发生变化而选中对象、日期和其余字段不变时，旧摘要可能继续显示原值。现已把这些实际显示字段加入缓存身份；数据不变时继续复用已有控件。

新增10项独立组件检查，直接检查实际摘要控件的文字。修复前有4项失败，修复后10项通过；[修复前记录](../reports/battle_summary_cache_v0230/before_fix.json)与[当前结果](../reports/battle_summary_tests.json)分别绑定受测HUD文件。该检查修改的是独立深拷贝夹具，不改发布剧本、不模拟玩家输入，也不作为实机画面或历史部署证据。

## 验证与复现

三种原生Windows视口分别覆盖1920×1080／100%、2400×1080／120%触屏布局，以及1280×720／150%大字体。输入通过Godot视口分发鼠标或触摸事件，没有直接发出按钮的`pressed`信号。合法移动经实际点选、预览与确认提交，再独立重放到相同战局和随机状态。

地图区域占比是相机与标注使用的矩形占视口比例，不是地表可见像素统计：三种尺寸约为78.63%、72.29%和61.12%。大字体保留更大的控件和文字空间。
