# 系列对标与实机修复 · 0.2.0

本版围绕用户反馈重做地图、兵种与 HUD，并补上沿路径行军、掷骰、开火、弹道、命中、反击、阵亡和航空演出。所有画面证据均由 Godot 原生视口直接保存；录像由 Godot MovieWriter 记录，再以 FFmpeg 编码为 MP4，没有把设计稿裁成游戏场景、叠字或拼成成品截图。

## 对标依据

已核验的官方产品资料为《世界征服者1945》及 2、3、4。官方目录未提供本次所称 5、6、7 的可核验资料，因此不以这些编号杜撰机制。

- [2 代官方 Google Play 页面](https://play.google.com/store/apps/details?hl=en_US&id=com.easytech.wc2)：将领兵科专长、工事、海空协同、军衔与地图缩放。

逐项阅读官方说明后再对照程序和实际原生运行。官方宣传视频网页未成功读取，浏览器连接也未成功；没有把未观看的视频写成观测证据。骰子界面是用户明确要求的游戏反馈，本作 ±17.5% 伤害变化是公开的本作规则，不声称复原 EasyTech 的未公开算法。

## 机制核对与落实

| 检查项 | 本版行为与验证 |
| --- | --- |
| 选中、移动、攻击与确认 | 蓝色可达格、合法红色目标、实际路线、目标纸卡；同一目标第二次点击或确认按钮执行，ESC 取消；命令带状态版本校验 |
| 行军与战争迷雾 | 沿实际经过的六边格插值，移动步态起伏、尘土/航迹/列车烟；按当前所在格隐藏不可见敌军，不泄露暗处移动路线 |
| 攻击与反击 | 掷骰先于开火；35% 时刻开火、弹道推进，65% 时刻受击与兵力变化，随后独立反击；死亡或压制不能反击，弹药与次数照常消耗 |
| 战斗播片 | 引擎内交战小窗展示实际进攻/防守单位、真实骰面、伤害与城防；地图同时演出；支持跳过、半速、双速和减少晃动 |
| 随机战况与存档 | 两枚六面骰的差值每点影响 3.5%，范围 ±17.5%；预览给出伤害/反击区间；存档保留随机流，预览与动画不抽取战斗随机数 |
| 炮兵、城防、驻军 | 遵守真实射程与最小射程；城防和守军分别扣减，城防伤害不溢出；致死伤害限于剩余兵力，原生炮击演示必须用合法命令 |
| 部队成长 | 存活部队有效攻击获 2 经验、击破获 4 经验、有效反击获 1 经验；20/50/80 晋升，攻击加成 3%/6%/10%，局内保存，不把游戏等级写成史实部队等级 |
| 自动作战 | 玩家 AI 与对手使用同一命令内核；每次命令等待演出，可随时停止；弹窗暂停；载入/弃局使旧异步计划失效；无效命令暂停保留战局 |
| 城市、生产与后勤 | 征募层数、生产队列、建设/整补/兵源、粮弹、补给线、铁路区间/车站运力继续参与同一规则事务 |
| 海军、运输与航空 | 船只装卸与航迹，航空侦察飞越/范围扫描，轰炸飞越与命中；机场出动、费用和敌我判定均由内核校验 |
| 将领、战法与成长 | 将领兵科适性、技能、冷却、指挥点、军衔、科技、勋章、奖励与成就继续沿用，战法和晋升增加可见反馈 |
| 战役/征服/军团 | 战役目标与时限、三个征服年代及外交援助、预算军团编组均可实际游玩；完整自动对局检查与单元检查分开报告 |

本作以 3/4 代的六边格与三种模式作为主要结构。初代的地域卡牌界面没有混入这套操作；二战坦克、导弹、核武与架空黑蝎内容也不移植到 1920 年代中国。铁路抢修、区间运力、粮弹和压制是本作的时代特色。

## 视觉修复

0.2.9以《欧陆战争6：1914》的可观察结构作为主要美术对照：自然绿色地面、蓝绿色水面、立体山脊、多个小人组成的军阵、醒目的势力边界和钢灰金属HUD。它继续使用自身的民国历史资料、Sub2独立素材和Godot原生几何，不把官方图片放入运行时。静态地形由运行时视口缓存，部队、边界、地名和战斗效果实时刷新；攻击预览保留目标信息，势力层可在全图与战术视图切换。当前版本接入117项 EW6 方向独立素材，包括32张旧斜向兵种图、64张四方位兵种图、地面/水面、山地、聚落、UI与战斗特效；平原第二材质、六边形明暗边缘和来源门控林地标记由Godot运行时绘制。

原 PNG、提示词与各次生成记录保留，工程文件与所选原图字节一致。双翼机 r001 因混入建筑被弃用，重新直接生成 r002，未裁图去除建筑。生成失败的装甲列车通过同一 Sub2 模型重试，没有换供应商或用程序绘制栅格图代替。

山脊仅放在有 SRTM 高程/起伏支持的位置，连续明暗与等高线来自真实高程。细海岸使用 Natural Earth 1:10m 的真实矢量，城市、铁路节点、通行格、军运连接与历史行政层不随插画移动。详细来源与年代精度见 [历史地理](07_历史地理与地图美术.md)。

## 历史逻辑修复

“山海关攻守”原起局错误地把山海关配置给奉军，再要求直军夺取。现改为 1924-10-06 窗口，直军控制山海关、秦皇岛，奉军由关外进攻、锦州为后方；关卡目标为坚守三阶段。依据为[中国大百科全书出版社《直奉山海关之战》公开摘要](https://js.bkzx.cn/item/xeg124286hfg)。三阶段是游戏目标，不冒充史实坚守天数；编队数量和格位仍是明确的战术抽象。

## 可复查的实际证据

- `reports/combat_presentation_tests.json`：预览纯度、伤害区间、主攻/反击骰、致死不反击、存档一致、跳过一致、路径插值、晋升、航空命中时机。
- `reports/automation_tests.json`：等待演出、停止、暂停、载入、弃局与旧异步计划失效。
- `reports/visual_playtest.json`：发布战役起局中的实际命令，以及从初始状态完整重放到最终状态的比较。
- `reports/support_playtest.json`：在发布的山海关防御剧本中，合法建设机场并经过正常敌我回合后执行实际飞越和轰炸；保留建设命令重放，玩家新建设施不宣称为历史机场部署。
- `reports/screenshots/visual_playtest/` 与交付录像：原生画面，未手工拼接。

完整检查数、双端构建版本和剩余验收范围见 [测试与验收](05_测试与验收.md)。当前规则版本为 9，战局 schema 为 2；0.1.3 旧战局在保留的旧版中继续，养成档案保留。桌面 X30 分辨率布局检查与 APK 签名/内容验证各自记录，未连接物理 X30 时不宣称真机已测。


任务纸卡按实际控制显示“夺取并守住”或“守住”，避免把奉军进入九门口的进攻起点写成已有控制。AI长局与短局的完整报告用`ai_dependency_evidence.json`绑定规则、AI、内容、保存代码、测试驱动及工程配置SHA；渲染修订时只有这些依赖及报告原字节相同才沿用已完成对局。界面、图形、演出、10组规则回归与双端构建另按最终运行源码重新验证。

后续0.2.1修复持续地图/战斗性能与全图取景，未改变本章规则或源素材；源码、实际EXE负载、三种分布完整AI阶段和整幅画面核对见[容量性能与渲染等价](12_容量性能与渲染等价.md)。


0.2.9将欧陆战争系列、尤其欧陆战争6作为后续美术和动效的主要方向。当前登记117项EW6方向Sub2独立素材，并强化实际领土分色、地形、军阵、钢灰面板与战斗小窗；单位移动、攻击和受击事件会保存最终四方位朝向。可复核的官方样本、核心结构比较、具体修改和未完成验收见[欧陆战争6对标与美术改版](16_欧陆战争6对标与美术改版.md)。
