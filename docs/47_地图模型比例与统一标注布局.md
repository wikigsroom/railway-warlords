# 0.2.29 · 地图模型比例与统一标注布局

状态：本轮技术验证完成。0.2.29双端当前构建、全部保留专项及正式EXE地图检查已通过；交付归档以[严格回执](../reports/map_composition_release_validation.json)为准。开发引擎视口、正式导出、规则回归、实际查看、正式美术和物理手机分别登记。

## 本轮解决的问题

武汉等密集地段的城市模型原先统一使用136×116逻辑像素，邻近港口、驻军和地名容易互相遮挡。旧标注主要避让其他文字与固定部队区域，没有使用各个建筑实际显示的轮廓。桥梁、渡口文字另画在静态底图中，无法随部队演出重新避让。

本轮统一模型尺寸、建筑占用区域与标注布局。蜂窝半径继续为48世界单位，城镇坐标、河流和铁路来源、规则编队位置及控制范围继续由原有真实地理与战局数据决定。

建筑继续保持原图宽高比，使用已有透明轮廓测量记录确定脚点与占用区域。驻军在原规则地格附近使用统一显示偏移，选择与寻路继续读取原地格。破损建筑、车站、港口和已登记的专属关隘继续使用各自来源素材。

本轮不增加栅格资产。完整原图由Godot引用并缩放，原始PNG、提示词与来源记录保留原字节。

## 统一标注

城市、非规则聚落及桥梁／渡口文字共用一套布局。城市名称优先，其次为聚落和交通说明。布局同时避让建筑轮廓、城市旗帜与城防条、可见编队、朝向标识、其他文字和HUD浮层；候选位置分布在对象四周，以较短的引线和较近的标注为优先。

城市字号保持18×UI缩放，村落为16×UI缩放，交通说明为15×UI缩放，均按屏幕尺寸计算。密集处的模型和文字分别布局，选中对象仍可从检查器读取信息。桥梁和渡口的地图符号保留来源位置，文字在前景重新安排。

移动和交战演出期间，标注占用区域读取演出中的编队位置；静止场景沿用缓存。前景与主图共享同一份实际建筑选材和朝向记录，避免同一城市的绘制素材与避让轮廓不一致。

## 验证与当前边界

[原生截图工具](../tools/capture_map_composition.py)检查武汉、北京、山海关、村落、中距离及桌面／手机比例／大字号布局。它独立比较输出的屏幕矩形，检查标注相互重叠、标注与模型／编队／交通符号重叠，以及关键地名保留情况。开发引擎运行与已验证EXE使用不同的证据模式。

自动矩形检查支持可读性判断，画面整体品质仍需查看完整原生视口。山体与平原衔接、河岸形态、地表层次、专属地标、完整兵种动作和整套界面精修仍属于后续工作。本轮不据局部比例调整宣布与《欧陆战争6》整体品质一致；Motorola X30物理验收仍待完成。

参考资料沿用已归档的[EasyTech官方图文教程](https://ew6w.ieasytech.com/manual/en/?fwg=website)，源图与SHA登记在原工作区的`output/research/european_war_6/sources.json`。官方图片仅作研究，本工程运行素材仍使用自身的Sub2原图。
