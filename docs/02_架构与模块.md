# 架构与模块

## 运行流程

`app/main.tscn → app/main.gd → ContentRegistry / ProfileRepository → StateBuilder → MatchController → CommandKernel.preview / resolve → 领域规则 → state + events → MapView / UI / GameAudio`。

界面与AI只提交命令。预览读取当前状态而不修改；提交首先校验版本、行动阵营、目标、费用和合法性，然后在独立事务状态上原子执行，更新视野/胜负/事件，再返回新状态。动态数据独立复制；递归只读的地图几何共享，涉及历史事件改格时按需复制。每次提交递增 `state_version`，拒绝重复旧命令。

0.2.6沿用0.2.4建立的格子和占位索引，以Vector2i坐标为键；它们只存在于线程独立的RulesQueryCache，不写入战局或存档。寻路图缓存记录当前可见格及其他通行输入的独立快照，排除不参与通行计算的探索与最后目击记录；可变编辑数据仍进行完整变更核对。

## 性能边界

占用格和铁路邻接缓存按数组身份/版本失效，视野只枚举每个来源附近格子；AI减少重复大状态复制。地图只绘制视窗附近的六边格和部队。图片源文件不缩放，Godot导入压缩并限制导入尺寸，单位512、建筑384、地块512、地景512、图标128。

规则规划、结算及存档I/O通过一个Godot原生线程串行执行，主线程按战局代号、起始状态和版本提交完整结果。查询缓存按线程隔离，一次寻路复用所属缓存。暂停保留计算结果；停止自动作战、返回菜单或读档使未提交结果失效。后台不访问场景树、控件、纹理和声音播放器。原生活动战局提交测量见[后台规则与响应性](13_后台规则与响应性.md)。

## 数据与存档

定义 JSON 与原设计的21表保持字节一致；编译后的地图与任务配方另存。城市经纬度采用百万分之一度整数，地图采用轴坐标 q/r，海岸和河流渲染点由真实源几何投影。

`runtime_match_state_v2.schema.json` 验证实际运行态；存档 envelope v2 包含 payload、SHA256、内容指纹、保存时间。运行规则版本7纳入内容指纹；后续改变结算行为须提升规则版本并提供显式兼容策略。0.1.0–0.1.3进行中战局继续使用保留的对应旧版本；养成档案可供0.2.2沿用，0.2.0进行中战局与本版兼容。

整回合结算恢复区间运力和反击额度、推进日期与天气/事件；本方阶段处理队列、施工、援助、收入、军饷、补给、状态/冷却、稳定、行动与指挥恢复。窗口、音效、动画不进入保存状态。

## 0.1.2规则扩展

`HistoricalRules`处理预检查后的历史所属事务与分日名称更新；`TurnRules`提供轮首调度。`VictoryRules`先统一判定失去战略反击能力的势力，再撤离相关动态记录，并保存同盟成员和期限积分表。`MovementRules.counterattack_reaches`使用分阶段AP、真实占位、通行和合法战斗终点；同一份状态通过`clone_transaction`保持输入快照不变。schema2采用ruleset5，新增结果字段为兼容的可选数据；进行中的旧指纹战局不静默替换规则。

0.1.3采用ruleset6，保护目标检查另外核对本方归属。`AtlasRelief`只读生成表现网格和地景布局；`MapView`分别缓存自然地理与年代行政线。新增来源/字体/边界与保存隔离检查见[10 地图绘制与可读性](10_地图绘制与可读性.md)。

0.2.0新增CombatRandom保存随机流、VeterancyRules局内经验、BattlePlayback演出快照和BattleCinema交战小窗。MatchController等待演出后继续自动命令，跳过/暂停/载入不重算命令。音频随时间线触发，退出显式停止并释放流。


AtlasSurface把真实海岸环平移到局部坐标后一次三角化，输出保留原坐标和UV的ArrayMesh。MapView与StrategicMinimap共用面缓存；跨年仅更新年代区划，不重做自然海岸。

0.2.2由MapView缓存地形与按单位原有顺序拆分的静态部队段。TextureRect以预乘Alpha混合显示SubViewport纹理；活动角色与静态段交错，原生前景层保持地名、路径和效果在部队上方。只有相关几何、可视性、铁路外观或静态单位数据改变才重建；血量变化不重复三角化海岸。单位排序复用预计算世界Y和原数组身份。CapacityFixture仅供明确开启的QA负载使用，测试部署不进入玩家场景目录。封存原生EXE、算法与完整视口像素证据见[容量性能与渲染等价](12_容量性能与渲染等价.md)。
